# D1 (`SHIPSTATION_DB`)

Schema: `src/backend/migrations/0001_init.sql` plus later numbered files. Sutton applies
migrations **on publish**. Do not edit `0001_init.sql` after a consumer has published —
add `0002_….sql`.
See create-digit-app [d1-migrations.md](../../../../../../.agents/skills/create-digit-app/reference/d1-migrations.md).

## Tables

| Table | Role |
| --- | --- |
| `shipstation_connection` | One live row per org (partial unique index on `organization_id` where `deleted = 0`). `api_version` is `v1` or `v2` (migration `0006_api_version.sql`, default `v2`). `api_key_encrypted` is `''` for new rows — the key is the `SHIPSTATION_API_KEY` app secret; legacy rows keep V2 ciphertext. Unused Phase 2 columns (`rate_*`, `defaults`, fee/email/address flags) stay at SQL defaults and are not returned by GET `/connection`. |
| `shipstation_carrier` | Catalog synced on connect and again when settings or the queue refresh. Soft-delete with the connection. A refresh writes `catalog_pull` only for carriers that were not already on this connection. |
| `shipstation_service` | Services under a carrier. Soft-delete with the connection. |
| `shipstation_webhook` | Legacy ShipStation webhook ids. Soft-deleted with the connection; the app no longer registers or processes webhooks. |
| `org_settings` | `default_fulfillment_method` (`manual` default after `0014_manual_push_default.sql`, or `scheduled`), `default_weight_oz` (default 16). Unused leftover columns: `sync_mode`, `push_when`, `lane_tag_id`, dims, `rate_strategy`. |
| `carrier_digit_map` | ShipStation `carrier_code` + `service_code` → Sutton `shippingCarriers` option (`0010`, `0013_carrier_service_map.sql`). Empty `ss_service_code` is a carrier-level default. `source` is `manual` or `fuzzy`. Service maps win over carrier defaults for writeback. **Push** reverse-maps Sutton option → a unique service-level row with `source = 'manual'` only (carrier defaults and `fuzzy` rows do not satisfy push; a `fuzzy`-only option resolves to `unconfirmed`). Do not auto-create Sutton options. |
| `shipstation_order_map` | Sutton shipment (and parent order) ↔ SS resource (`ss_shipment_id` is a V2 shipment id or V1 order id). Unique on `(connection_id, digit_shipment_id)` (`0008_shipment_map.sql`). `ss_label_id` after poll/writeback. `tracking_status` is ShipStation label tracking status (`0011_tracking_status.sql`). `label_pdf_base64` stores V1 label PDFs only (`0009_label_rates.sql`). `service_code` / `service_name` from the purchased label (`0013`). |
| `package_selection` | Queue package-type choice per Sutton pack container (`0016_package_selection.sql`). Unique on `(connection_id, digit_container_id)` where `deleted = 0`. Not written to Sutton. `source` is `custom`, `carrier`, or `shipstation` (pull overwrite). Weight stays empty until a pull. A new connection id after reconnect drops prior choices. |
| `shipstation_seen_package` | Package codes already pulled for this connection (`0017_seen_package.sql`). Used so the activity log records a package only the first time ShipStation returns it. |
| `activity_log` | Operator and job outcomes (`GET /sync/activity`). Optional `channel_id`, `external_order_id`. |
| `channel_connection` | Per-org store metadata (no secrets). |
| `channel_order_map` | Sutton order ↔ external store order. |
| `webhook_delivery` | Unused leftover table from channel inbound scaffolding. |
| `app_config` | Generated `ENCRYPTION_KEY` only (decrypts legacy `shipstation_connection` ciphertext). Migration `0007_drop_legacy_app_secrets.sql` removes old in-app secret rows; setup secrets are Sutton App Secrets (`env`) only. |
| `shipment_label` | Audit row inserted on writeback. FKs survive disconnect. |

## Rules

- Soft-delete (`deleted = 0/1`); do not hard-delete connections used by `shipment_label`.
- `api_key_encrypted` is only read in `liveCredentials` / disconnect, as a legacy V2
  fallback after `SHIPSTATION_API_KEY`. Public `SELECT`s must omit it.
- Reconnect = new connection row + full carrier re-sync (old row stays deleted).
- Dropping the one-live-connection index is how multi-account would ship later — do not drop it unless the user asks.
- Error / activity contract: [error-handling.md](error-handling.md).
