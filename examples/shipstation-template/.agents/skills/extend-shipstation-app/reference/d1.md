# D1 (`SHIPSTATION_DB`)

Schema: `src/backend/migrations/0001_init.sql`. Digit applies migrations **on publish**.
Do not edit `0001_init.sql` after a consumer has published — add `0002_….sql`.
See create-digit-app [d1-migrations.md](../../../../../../.agents/skills/create-digit-app/reference/d1-migrations.md).

## Tables

| Table | Role |
| --- | --- |
| `shipstation_connection` | One live row per org (partial unique index on `organization_id` where `deleted = 0`). Holds encrypted API key and behavior settings. |
| `shipstation_carrier` | Catalog synced on connect. Soft-delete with the connection. |
| `shipstation_service` | Services under a carrier. Soft-delete with the connection. |
| `shipstation_webhook` | ShipStation webhook ids registered for this connection. Soft-deleted on disconnect. |
| `org_settings` | Org default fulfillment method (not a Digit `moduleSettings` field). |
| `shipment_label` | Audit stub (connection + optional carrier FKs). Label purchase is not implemented; keep FKs if you add rows so disconnect can leave them readable. |

## Rules

- Soft-delete (`deleted = 0/1`); do not hard-delete connections used by `shipment_label`.
- `api_key_encrypted` is only loaded in `liveConnectionWithSecret` (disconnect). Public
  `SELECT`s must omit it.
- Reconnect = new connection row + full carrier re-sync (old row stays deleted).
- Dropping the one-live-connection index is how multi-account would ship later — do not
  drop it unless the user asks.
