# D1 (`SHIPSTATION_DB`)

Schema: `src/backend/migrations/0001_init.sql` plus later numbered files. Digit applies
migrations **on publish**. Do not edit `0001_init.sql` after a consumer has published —
add `0002_….sql`.
See create-digit-app [d1-migrations.md](../../../../../../.agents/skills/create-digit-app/reference/d1-migrations.md).

## Tables

| Table | Role |
| --- | --- |
| `shipstation_connection` | One live row per org (partial unique index on `organization_id` where `deleted = 0`). `api_key_encrypted` is `''` for new rows — the key is the `SHIPSTATION_API_KEY` app secret; legacy rows keep their ciphertext. Unused Phase 2 columns (`rate_*`, `defaults`, fee/email/address flags) stay at SQL defaults and are not returned by GET `/connection`. |
| `shipstation_carrier` | Catalog synced on connect. Soft-delete with the connection. |
| `shipstation_service` | Services under a carrier. Soft-delete with the connection. |
| `shipstation_webhook` | ShipStation webhook ids. Soft-deleted on disconnect. |
| `org_settings` | `default_fulfillment_method`, `sync_mode` (`digit_to_ss` \| `ss_to_digit`), `push_when` (`fully_packed` \| `inventory_available`), `lane_tag_id` (nullable). |
| `shipstation_order_map` | Digit order ↔ SS shipment, source, push_status, tracking, optional label cost (storage only). |
| `activity_log` | Operator and job outcomes (`GET /sync/activity`). Optional `channel_id`, `external_order_id`. |
| `channel_connection` | Per-org store metadata (no secrets). |
| `channel_order_map` | Digit order ↔ external store order. |
| `webhook_delivery` | Inbound idempotency per channel. |
| `app_config` | Generated encryption key, plus read-only legacy `API_TOKEN_DIGIT` / `PUBLIC_WEBHOOK_URL` rows saved before those moved to Digit app secrets. |
| `shipment_label` | Audit row inserted on writeback. FKs survive disconnect. |

## Rules

- Soft-delete (`deleted = 0/1`); do not hard-delete connections used by `shipment_label`.
- `api_key_encrypted` is only read in `liveApiKey` / disconnect, as a legacy fallback after
  `SHIPSTATION_API_KEY`. Public `SELECT`s must omit it.
- Reconnect = new connection row + full carrier re-sync (old row stays deleted).
- Dropping the one-live-connection index is how multi-account would ship later — do not drop it unless the user asks.
- Error / activity contract: [error-handling.md](error-handling.md).
